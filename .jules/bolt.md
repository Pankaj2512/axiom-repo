## 2026-07-28 - Optimizing O(N) array calculations in React components that consume Context
**Learning:** In React components like StatsGrid that consume multiple context hooks (e.g. useProgress, useStreaks, useRevisionQueue), the component re-renders whenever ANY of those contexts update. If a component performs expensive synchronous calculations derived from one context (like reducing or filtering a large 'progress' array), those O(N) calculations will run unnecessarily when an unrelated context updates. Also, static data (like the total number of items from static track definitions) should be precomputed outside the component to avoid any calculations during rendering.
**Action:** Extract static pre-computations entirely outside the component body. Wrap expensive derivations of mutable context state in `React.useMemo` with the specific state dependency (e.g. `[progress]`) to avoid recalculations triggered by unrelated state changes. Combine multiple O(N) `.filter()` passes into a single `.reduce()` pass for better performance.
