## 2024-07-12 - Accessibility patterns for nested interactive elements in ItemCard
**Learning:** Adding interactive elements (like icon buttons and anchors) inside a link wrapper like Next.js `Link` requires explicitly defining accessibility properties. Icon-only elements are effectively invisible to screen readers without `aria-label`. Similarly, a button acting as a dropdown trigger lacks context unless it has `aria-expanded` and `aria-haspopup`. Furthermore, elements must have explicit focus outlines (`focus-visible:ring-2`) to show keyboard focus since browser defaults often conflict or get suppressed in card layouts.
**Action:** When creating list/card elements wrapped in `Link` that have internal actions, always verify that inner elements have `aria-label`, handle keyboard focus visibly with `focus-visible` classes, and declare appropriate popups using `aria-haspopup` and `aria-expanded`.
